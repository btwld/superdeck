# Block layouts

SuperDeck lays out every slide on a logical `1280 x 720` canvas. Sections form
vertical rows; the blocks inside each section form horizontal columns.

## The two layout axes

```text
slide
├── section 1             vertical allocation between sections
│   ├── block A           horizontal allocation inside the section
│   └── block B
└── section 2
    └── block C
```

`flex` controls both axes:

- A section's positive integer `flex` is its height relative to sibling sections.
- A block's positive integer `flex` is its width relative to sibling blocks.

```markdown
@section { flex: 1 }
@block
Top row

@section { flex: 2 }
@block { flex: 2 }
Wide column

@block { flex: 1 }
Narrow column
```

If a slide has no directives, SuperDeck creates one section containing one
Markdown block. Multiple `@block` directives without `@section` share one
implicit section.

## Four independent geometry controls

Keep these controls separate:

1. The slide container style supplies the outer slide inset.
2. `@section { spacing: ... }` creates gaps between sibling blocks.
3. A block's `padding` creates an inset inside that block.
4. `align` places the content inside the remaining content rectangle.

```markdown
@section {
  spacing: 32
  align: center
}

@block { padding: 0 }
Edge to edge inside this column

@block { padding: 16 }
Uniform internal inset

@block {
  padding: { horizontal: 48, vertical: 24 }
  align: bottomRight
}
Independent axes and an explicit alignment override
```

Section spacing exists only between blocks—never before the first or after the
last. When a requested total gap is wider than the section, SuperDeck clamps
the actual gap so every block remains inside the section.

## Padding forms

Content and widget blocks accept exactly three padding forms:

```markdown
@block { padding: 16 }
@block { padding: { horizontal: 24, vertical: 16 } }
@block { padding: { top: 12, right: 24, bottom: 12, left: 24 } }
```

Omitted keys in an object are zero. Do not mix `horizontal`/`vertical` with
physical edge keys. Empty objects, unknown keys, negative values, `NaN`, and
infinity are invalid.

An omitted padding override retains the resolved Mix block-container padding.
A present override replaces only that resolved padding after active variants;
margin, border, decoration, animation, modifiers, and variant behavior remain.

## Alignment inheritance

The effective alignment for each block is:

```text
block align → section align → centerLeft
```

Use section alignment for a shared default and block alignment for exceptions:

```markdown
@section { align: topCenter }

@block
Inherits topCenter

@block { align: bottomRight }
Overrides the section
```

All nine values are supported: `topLeft`, `topCenter`, `topRight`,
`centerLeft`, `center`, `centerRight`, `bottomLeft`, `bottomCenter`, and
`bottomRight`.

## Image framing

`fit` controls how image pixels fit their frame. `scale` enlarges or shrinks
the painted pixels without changing the frame or the block's flex geometry.

```markdown
@image {
  src: assets/screenshot.png
  fit: cover
  width: 640
  height: 360
  scale: 1.25
  align: center
}
```

Scaled pixels are clipped to explicit `width`/`height` when supplied, otherwise
to the block's effective content rectangle. The transform origin uses the
effective block alignment. `scale` defaults to `1` and must be finite and
greater than zero.

For a full-canvas image, use `layout: fullscreen`, one image block, an explicit
`1280 x 720` frame, `fit: cover`, and `padding: 0`. Fullscreen changes chrome;
it does not change the image framing rules.

## Overflow and debugging

Non-scrollable content is hard-clipped. Use `scrollable: true` on a content or
widget block when the audience should be able to reach overflowed content.

With `DeckOptions(debug: true)`, supported non-scrollable Markdown overflow gets
a red indicator and a deduplicated console message containing the slide key,
block key, available size, measured size, and overflow axis. The live probe
observes the existing Markdown render; it does not change wrapping constraints.
It intentionally does not rebuild or intrinsically measure arbitrary custom
widgets, and static capture remains diagnostic-free.

## Next-major migration

Two inputs change semantics in the next major release:

- `flex` must be a positive integer. Replace zero or negative values.
- Section alignment now applies to children without explicit block alignment.
  Add an explicit child alignment where the old no-op behavior must remain.

After adopting `spacing` or `padding`, rebuild `.superdeck/superdeck.json`.
Downgrading to 1.x requires removing the new authoring properties and rebuilding
the contract with the 1.x toolchain.
