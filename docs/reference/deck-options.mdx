# Runtime API reference

SuperDeck v2 is configured through three public types:

- `DeckSource` for content origin and watch behavior
- `DeckRuntimeConfig` for startup-only operational paths
- `DeckTheme` for render composition, custom widgets, templates, and slide frame widgets

The canonical bootstrap shape is:

```dart
Future<void> main() async {
  final runtime = await SuperDeckRuntime.create(
    source: const DeckSource.local(
      slidesPath: 'slides.md',
      watch: true,
    ),
    runtimeConfig: const DeckRuntimeConfig(),
    theme: DeckTheme(
      widgets: const {
        'twitter': TwitterWidgetDefinition(),
      },
      frame: SlideFrame(
        header: CustomHeaderPart(),
        footer: CustomFooterPart(),
        background: CustomBackgroundPart(),
      ),
      debug: true,
    ),
  );

  runApp(SuperDeckApp(runtime: runtime));
}
```

## `DeckSource`

### `DeckSource.local`
Use a local markdown source and optionally watch it for changes.

```dart
const DeckSource.local(
  slidesPath: 'slides.md',
  watch: true,
)
```

### `DeckSource.bundle`
Use prebuilt bundled artifacts.

```dart
const DeckSource.bundle(
  deckAssetPath: '.superdeck/superdeck.json',
)
```

## `DeckRuntimeConfig`

Startup-only operational paths:

```dart
const DeckRuntimeConfig(
  projectDir: '.',
  outputDir: '.superdeck',
  assetsPath: 'assets',
)
```

## `DeckTheme`

Render composition and slide-level composition points:

```dart
DeckTheme(
  baseStyle: SlideStyle(),
  styles: {
    'title': SlideStyle(),
  },
  widgets: const {
    'twitter': TwitterWidgetDefinition(),
  },
  frame: SlideFrame(
    header: CustomHeaderPart(),
    footer: CustomFooterPart(),
    background: CustomBackgroundPart(),
  ),
  debug: true,
)
```

### `baseStyle`
Base style for all slides.

### `styles`
Named style variants for frontmatter such as:

```markdown
---
style: title
---
```

### `widgets`
Custom widget definitions keyed by widget name.

### `frame`
Slide-wide header, footer, and background widgets.

### `templates` and `defaultTemplate`
Named slide templates and the deck-level fallback template.

### `debug`
Enables visual debugging aids for slide layout design.

### `SuperDeckRuntime.extensions`
Behavioral/runtime add-ons that replace the old plugin-first surface.

## `WidgetDefinition` example

```dart
import 'package:flutter/widgets.dart';
import 'package:superdeck/superdeck.dart';

class TwitterWidgetDefinition extends WidgetDefinition<Map<String, Object?>> {
  const TwitterWidgetDefinition();

  @override
  Map<String, Object?> parse(Map<String, Object?> args) => args;

  @override
  Widget build(BuildContext context, Map<String, Object?> args) {
    final username = args['username'] as String? ?? '';
    final tweetId = args['tweetId'] as String? ?? '';

    return Text('Twitter: @$username ($tweetId)');
  }
}
```

## Best practices

1. Use `DeckSource.local(watch: true)` during development.
2. Keep `DeckRuntimeConfig` limited to startup-only operational concerns.
3. Put styles, widgets, frame widgets, templates, and debug visuals on `DeckTheme`.
4. Keep behavioral add-ons on `SuperDeckRuntime.extensions`.
5. Enable `debug: true` while designing layouts.
