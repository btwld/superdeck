# Runtime API reference

The current SuperDeck bootstrap surface is:

- `initializeSuperDeck()` for one-time startup work
- `DeckConfig` for deck origin and watch behavior
- `SuperDeckProvider` for loading, rebuild, and error ownership
- `SuperDeckApp` for rendering a loaded `Deck`
- `DeckTheme` for render composition
- `DeckExtension` for behavior and extra UI

## Canonical bootstrap

```dart
import 'package:flutter/foundation.dart';
import 'package:flutter/widgets.dart';
import 'package:superdeck/superdeck.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await initializeSuperDeck();

  final config = kIsWeb
      ? const DeckConfig.bundle()
      : const DeckConfig.local(
          slidesPath: 'slides.md',
          watch: true,
        );

  runApp(
    SuperDeckProvider(
      config: config,
      builder: (context, deck) => SuperDeckApp(
        deck: deck,
        theme: DeckTheme(
          widgets: const {
            'twitter': TwitterBlockDefinition(),
          },
          frame: SlideFrame(
            header: CustomHeaderPart(),
            footer: CustomFooterPart(),
            background: CustomBackgroundPart(),
          ),
          debug: true,
        ),
      ),
    ),
  );
}
```

## `initializeSuperDeck()`

Runs one-time startup work before `runApp()`.

Use it to:

- initialize framework dependencies
- initialize `DeckExtension`s
- keep startup concerns out of widget constructors

## `DeckConfig`

`DeckConfig` selects where the deck comes from.

### `DeckConfig.local`

Use a local `slides.md` source and optionally watch it for changes.

```dart
const DeckConfig.local(
  slidesPath: 'slides.md',
  watch: true,
  projectDir: '.',
  outputDir: '.superdeck',
  assetsPath: 'assets',
)
```

### `DeckConfig.bundle`

Use bundled deck artifacts for web/test/release-style runtimes.

```dart
const DeckConfig.bundle(
  deckAssetPath: '.superdeck/superdeck.json',
  projectDir: '.',
  outputDir: '.superdeck',
  assetsPath: 'assets',
)
```

## `SuperDeckProvider`

`SuperDeckProvider` owns:

- deck loading
- local file-watch rebuilds
- loading/error/rebuild UI

It calls `builder` only when a loaded `Deck` is available.

```dart
SuperDeckProvider(
  config: config,
  builder: (context, deck) => SuperDeckApp(
    deck: deck,
    theme: const DeckTheme(),
  ),
)
```

## `SuperDeckApp`

`SuperDeckApp` is the render/runtime shell for a loaded deck.

```dart
SuperDeckApp(
  deck: deck,
  theme: DeckTheme(
    baseStyle: SlideStyle(),
    styles: {
      'title': SlideStyle(),
    },
    widgets: const {
      'twitter': TwitterBlockDefinition(),
    },
    frame: SlideFrame(
      header: CustomHeaderPart(),
      footer: CustomFooterPart(),
      background: CustomBackgroundPart(),
    ),
    debug: true,
  ),
  extensions: const [
    PresenterToolsExtension(),
  ],
)
```

## `DeckTheme`

`DeckTheme` owns render composition:

- `baseStyle`
- `styles`
- `widgets`
- `frame`
- `templates`
- `defaultTemplate`
- `debug`

Custom widget blocks are registered as `BlockDefinition`s keyed by name.

```dart
class TwitterBlockDefinition extends BlockDefinition<Map<String, Object?>> {
  const TwitterBlockDefinition();

  @override
  Map<String, Object?> parse(Map<String, Object?> args) => args;

  @override
  Widget build(BuildContext context, Map<String, Object?> args) {
    final username = args['username'] as String? ?? '';
    final tweetId = args['tweetId'] as String? ?? '';
    return Text('Twitter: @$username ($tweetId)');
  }
}
```

## Best practices

1. Use `DeckConfig.local(watch: true)` during local development.
2. Use `DeckConfig.bundle()` for bundled/web-style deployments.
3. Keep loading/build/watch ownership in `SuperDeckProvider`.
4. Keep styles, widgets, templates, and slide frame parts on `DeckTheme`.
5. Keep behavioral add-ons on `DeckExtension`.
