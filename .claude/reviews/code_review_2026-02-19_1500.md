## Part 1: Code Quality

### BLOCKER

**F7 — Correctness: Unconditional export of `dart:io`-dependent file breaks web compilation**
- **Location**: `packages/core/lib/superdeck_core.dart:11`
- **Issue**: `asset_cache_store_io.dart` (which imports `dart:io`) is unconditionally exported from the `superdeck_core` barrel file. Since `superdeck_core` is consumed by the `superdeck` package which targets web, this causes a compile-time error on web. The `superdeck` package already handles platform dispatch correctly with conditional exports in `lib/src/utils/asset_cache_store.dart` — this core barrel export bypasses that pattern entirely.
- **Action**: Remove the unconditional `export 'src/asset_cache_store_io.dart';` from `superdeck_core.dart`. Only export the abstract `AssetCacheStore` interface. Platform implementations should be imported directly where needed or via conditional exports.

### CRITICAL

**F8 — Correctness: `imageCache.evict` silently fails on web — stale thumbnails persist**
- **Location**: `packages/superdeck/lib/src/export/async_thumbnail.dart:42`
- **Issue**: On web, `getImageProvider(currentUri)` for `data:` URIs creates a new `MemoryImage(uri.data.contentAsBytes())`. Since `MemoryImage.==` uses reference equality on `Uint8List` (not content equality), the eviction key will never match the entry already in Flutter's `imageCache`. Force-regenerated thumbnails won't replace stale ones on web.
- **Evidence**: `cache_image_widget.dart:22-26` creates `MemoryImage(bytes)` from `uri.data?.contentAsBytes()` — each call produces a new `Uint8List` instance. At `async_thumbnail.dart:42`, `imageCache.evict(getImageProvider(currentUri))` creates another `MemoryImage` with a *different* `Uint8List` reference, so eviction is a no-op.
- **Action**: Either (a) cache the `ImageProvider` instance alongside the URI so the same reference is used for eviction, or (b) use `imageCache.clear()` as a fallback on web, or (c) implement content-based equality for the provider key.

### SHOULD_FIX

**F1 — Consistency: Duplicated asset key validation**
- **Location**: `packages/core/lib/src/asset_cache_store_io.dart:49`
- **Issue**: `_normalizeAssetKey` is reimplemented identically in 3 files: `core/asset_cache_store_io.dart`, `superdeck/utils/asset_cache_store_io.dart`, and `superdeck/utils/asset_cache_store_web.dart`.
- **Action**: Extract a shared validator in `core` and reuse it to avoid drift.

**F2 — Correctness: Broad exception swallowing in web cache**
- **Location**: `packages/superdeck/lib/src/utils/asset_cache_store_web.dart:45`
- **Issue**: `resolve()` catches `on Object` which swallows all errors including programming bugs, converting them silently to cache misses.
- **Action**: Catch only expected `FlutterError` for missing assets; surface unexpected errors via logging or rethrow.

**F3 — ControlFlow: DeckController has too many responsibilities**
- **Location**: `packages/superdeck/lib/src/deck/deck_controller.dart:28`
- **Issue**: Single class manages deck loading, router integration, navigation, UI flags, thumbnail cache, and disposal across 400+ lines.
- **Action**: Consider splitting into focused collaborators (deck loading, navigation state, thumbnail state) with DeckController as orchestrator. *Note: this is pre-existing, not introduced by this PR.*

**F5 — Clarity: Boolean control flags passed positionally**
- **Location**: `packages/superdeck/lib/src/export/async_thumbnail.dart:8`
- **Issue**: `AsyncFileGenerator` uses positional `bool force`, leading to ambiguous calls like `thumbnail.load(context, true)`.
- **Action**: Replace with named parameter `{required bool force}`.

### NOTE

**F4 — Debt: Leftover editorial comments in AppShell**
- **Location**: `packages/superdeck/lib/src/ui/app_shell.dart:138`
- **Issue**: Comments like "adjust as needed" and "uncomment if needed" read like review artifacts.
- **Action**: Remove non-actionable comments.

**F6 — Security: Unbounded in-memory cache on web**
- **Location**: `packages/superdeck/lib/src/utils/asset_cache_store_web.dart:12`
- **Issue**: `_cache` is an unbounded `Map<String, Uint8List>` with no eviction or size limit.
- **Action**: Consider adding LRU or max-size eviction for long-running sessions.
